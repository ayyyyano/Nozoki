# 故障排查

| 现象                         | 检查                                                                                                                                    |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 线上首页提示存储不可用       | 核对 D1 绑定名 `DB`、数据库 ID 与迁移状态。自部署检查 SQLite 路径和权限。                                                               |
| 构建提示 Worker 名称不一致   | 控制台里的 Worker 名和 `wrangler.jsonc` 的 `name` 应相同。                                                                              |
| 构建提示运行时版本不符       | 使用仓库锁定的 Node 和 pnpm 版本。Workers Builds 的构建命令为 `pnpm build`。                                                            |
| 登录失败或切换域名后不能登录 | 先检查 `AUTH_ORIGIN`、管理员邮箱和运行时 Secret，再核对反代 `Host`。                                                                    |
| 来源目标未批准               | 修改地址或凭据后重新「测试并批准」，并保存全局配置。                                                                                    |
| 来源提示协议不匹配           | 检查该版本的必要端点是否返回预期 JSON。反代登录页、重定向和交互验证也可能导致失败。                                                     |
| 首页数据过期                 | 打开模块详情查看观测时间。核对 Cron、来源和对应模块的开关、凭据及上游响应。卡片刷新按钮只重读已保存数据、不触发采集，不能单独解决过期。 |
| CLIProxyAPI 的日用量为空     | 检查统计开关、队列保留时间、采集间隔和是否有其他消费者。见[按日用量](/integrations/cliproxyapi.md#按日用量)。                           |
| UptimeFlare 只显示 ID        | 检查 API 的 `name` 字段，也可在后台设别名。见[服务监控](/integrations/monitoring.md)。                                                  |

测试成功表示当时的连接和协议验证通过。采集结果仍取决于模块启用状态、刷新间隔与上游可用性。
